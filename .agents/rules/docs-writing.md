# 文件撰寫規範 (Documentation Writing Guidelines)

本規範適用於專案內所有技術文件、說明指南與 README 的撰寫與維護。

## 1. 結構與排版
- **階層分明**：遵循標準 Markdown 標題層級（H1 `#` 為文件主標題，H2 `##` 為主要章節，H3 `###` 為子項目），不可跳級使用。
- **條理清單**：優先使用項目符號（Bullet points）或編號清單（Numbered lists）整理多項內容，避免過長段落。
- **重點標示**：重要觀念、設定參數、路徑或快捷鍵以 `code` 或 **粗體** 明確標籤。

## 2. 語系與專業術語
- **繁體中文為主**：文字說明一律使用臺灣習慣之繁體中文（zh-TW）。
- **專有名詞保留原名**：程式語言關鍵字、API 名稱、函式庫、Git 指令等保留英文原名（例如：`commit`, `push`, `localStorage`, `DOM`）。
- **前後一致**：相同的概念與術語在整份文件中需保持名詞一致。

## 3. 程式碼區塊規範
- **明確標記語言**：所有程式碼區塊必須標示語法高亮標籤（如 `bash`, `javascript`, `html`, `css`, `json`, `markdown` 等）。
- **完整且可執行**：程式碼範例應具備代表性，並提供必要的註解說明。

## 4. 提示與警示區塊
- 適當運用 GitHub 風格的 Alert 語法加強重點提示：
  > [!NOTE]
  > 提供背景脈絡、補充資訊或相關說明。

  > [!TIP]
  > 提供操作技巧、效率建議或最佳實踐。

  > [!IMPORTANT]
  > 標示必備要件、關鍵步驟或必須注意之限制。

## 5. 文件維護與同步
- **隨程式碼同步更新**：當新增功能、重構或修改 API/參數時，必須同步更新對應的文件，確保文件與程式碼一致。
- **路徑與連結有效性**：文件中引用的內部檔案路徑或外部連結需確保有效且可點擊存取。
